# Análisis del problema

## Ticket
El programa implementa el algoritmo de puntos de articulación (articulation points) mediante DFS iterativo con low-link, para resolver ABC334G (calcular la esperanza del número de componentes conexas tras eliminar una celda negra al azar). Pasa en casos pequeños (sample00, testcase00/03/07) pero falla sistemáticamente en casos grandes (testcase10, 14, 17, 20, 24, 27), lo cual sugiere un bug de **conteo/duplicación** que solo se manifiesta cuando la estructura del grafo es suficientemente compleja (vértices de articulación con múltiples hijos calificantes), no un error de lógica DFS básica.

## Hallazgos en los logs
- Casos pequeños (grillas simples, pocos puntos de articulación con más de un hijo "colgante") producen resultados correctos.
- Casos grandes (grillas de ~1000x1000, con múltiples componentes bicohesivas complejas) producen resultados incorrectos, aunque el programa no arroja excepciones: es un error silencioso de cálculo numérico (módulo).

## Relación con el código fuente
El bloque crítico es:

```python
Articulation = []
...
for i in LIST:
    if i == ROOT:
        continue
    if DFS_Parent[i] == ROOT:
        ROOT_DEG += 1
    if DFS_ORD[DFS_Parent[i]] <= LOWLINK[i] and DFS_Parent[i] != ROOT:
        Articulation.append(DFS_Parent[i])

for x in Articulation+[ROOT]:
    if x==ROOT:
        ...
    else:
        now=0
        for c in DFS_Child[x]:
            if DFS_ORD[x]<=LOWLINK[c]:
                now+=1
    LANS+=now
```

Si un vértice `p` (no raíz) tiene **más de un hijo** `c1, c2, ...` que satisface la condición de articulación (`DFS_ORD[p] <= LOWLINK[c]`), entonces `Articulation.append(DFS_Parent[i])` inserta `p` **una vez por cada hijo calificante**. Como resultado, `p` aparece repetido `k` veces en la lista `Articulation` (siendo `k` el número de hijos calificantes).

Luego, en el bucle `for x in Articulation+[ROOT]:`, para cada aparición repetida de `p` se **recalcula el mismo valor `now = k`** (la suma total de hijos calificantes de `p`) y se suma a `LANS` en cada iteración. Esto provoca que la contribución de `p` a `LANS` sea `k*k` en lugar del valor correcto `k`.

## Ejemplo de ejecución
Supongamos un vértice `p` (no raíz) con 2 hijos `c1` y `c2` en el árbol DFS, ambos cumpliendo `DFS_ORD[p] <= LOWLINK[c]`. Entonces:
- `Articulation` contendrá `[p, p]` (agregado dos veces).
- En el bucle final, para cada una de las dos apariciones de `p`, se calcula `now = 2` (cuenta ambos hijos).
- Se suma `LANS += 2` dos veces → total `4`.
- El valor correcto que debería sumarse es solo `2` (una sola vez).

Esto infla `LANS`, y por ende el resultado final `(LANS+ANS*SUM)*pow(SUM,mod-2,mod)%mod` queda incorrecto, explicando la discrepancia observada en los tests grandes donde existen múltiples puntos de articulación con más de un "hijo colgante".

## Solución propuesta
Deduplicar la lista `Articulation` antes de iterar sobre ella, por ejemplo:

```python
for x in list(set(Articulation)) + [ROOT]:
```

o construir `Articulation` como un `set()` desde el inicio, evitando inserciones repetidas del mismo vértice.
