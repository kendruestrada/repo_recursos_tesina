### Analysis

**Archivo:** `lambda/report.py`

Las variables `count` y `TEMPLATE_CACHE` son globales a nivel de modulo (lineas 8-9). En AWS Lambda, el contenedor de ejecucion se reutiliza entre invocaciones calidas (warm starts). Esto provoca que:

- `count` se incremente en cada llamada: `count += 1` (linea 64)
- La lista generada en linea 81 crece proporcionalmente al contador:
  ```python
  my_list = [i for i in range(100000 * count)]
  ```
  - Invocacion 1: 100,000 elementos
  - Invocacion 2: 200,000 elementos
  - Invocacion N: N * 100,000 elementos
- Cada lista se acumula en `TEMPLATE_CACHE` (linea 84) que **nunca se limpia**
- La configuracion `provisionedConcurrentExecutions: 1` en `test_009-stack.ts` (linea 44) **garantiza** que el contenedor permanece calido, activando sistematicamente el leak

**Ejemplo de ejecucion hipotetica:**

| Invocacion | `count` | Tamanio `my_list` aprox. | `TEMPLATE_CACHE` acumulado |
|---|---|---|---|
| 1 | 1 | ~800 KB | 1 entrada |
| 5 | 5 | ~4 MB | 5 entradas (~12 MB total) |
| 20 | 20 | ~16 MB | 20 entradas (~160 MB total) |

Con `memorySize: 128` MB (linea 35 de `test_009-stack.ts`), el proceso crashea con un error de memoria antes de la invocacion 20.

**Steps to reproduce:**
1. Desplegar el stack
2. Invocar el endpoint `GET /report` repetidamente (minimo 10-15 veces con contenedor caliente)
3. Observar que el Lambda empieza a retornar errores 500 por OOM

**Expected:** La funcion genera y retorna el PDF sin consumo creciente de memoria.

**Actual:** Cada invocacion acumula listas mas grandes en `TEMPLATE_CACHE`, agotando los 128 MB de memoria.

**Location:** `lambda/report.py:62-84` — funcion `template()`

### Solution

Eliminar `TEMPLATE_CACHE`, `count` y `my_list` de la funcion `template()`, ya que no tienen ninguna utilidad funcional para la generacion del reporte. El objeto `Template` de fpdf no necesita ser cacheado entre invocaciones.

## [BUG-2]: Timeout de Lambda Excede el Limite de API Gateway

### Summary: El timeout de Lambda (35s) supera el maximo de integracion de API Gateway (29s), causando errores 504 Gateway Timeout para requests lentos.

### Severity: High

### Root Cause Analysis

**Archivo:** `lib/test_009-stack.ts:37`

```typescript
timeout: Duration.seconds(35),
```

API Gateway impone un timeout maximo de integracion de **29 segundos**. Si el Lambda demora mas de 29 segundos (posible dado el procesamiento de 50 parrafos de texto y generacion de PDF), API Gateway retorna un `504 Gateway Timeout` al cliente aunque el Lambda aun este ejecutandose.

**Expected:** El Lambda completa y API Gateway retorna la respuesta al cliente.

**Actual:** Para requests que superen 29s, API Gateway interrumpe la conexion con 504, aunque el Lambda continue ejecutandose hasta los 35s desperdiciando recursos.

**Location:** `lib/test_009-stack.ts:37`

### Solution

Reducir el timeout del Lambda a un valor menor o igual a 29 segundos:

```typescript
timeout: Duration.seconds(29),
```

## [BUG-3]: Llamada a `template()` Puede Abortar una Respuesta PDF ya Generada

### Summary: La funcion `template()` se invoca dentro del bloque `try` despues de generar el PDF (linea 30), por lo que cualquier excepcion en ella descarta el PDF correctamente generado y retorna un error 500.

### Severity: Medium

### Root Cause Analysis

**Archivo:** `lambda/report.py:26-30`

```python
pdf_bytes = pdf.output(dest='S')          # PDF listo
encoded_pdf = base64.b64encode(pdf_bytes).decode('utf-8')  # encoding listo

template()   # si falla, cae al except → retorna 500, perdiendo encoded_pdf
```

El PDF fue generado correctamente en la linea 26 y codificado en la 28. Sin embargo, `template()` en la linea 30 puede lanzar una excepcion (por OOM, error de escritura en `/tmp`, etc.), lo que provoca que el bloque `except` (linea 44) retorne un 500, descartando el PDF valido.

**Expected:** El PDF generado es retornado independientemente del exito de `template()`.

**Actual:** Un fallo en `template()` resulta en un error 500, aunque el PDF estuviera listo para entregar.

**Location:** `lambda/report.py:30`

### Solution

Mover la llamada a `template()` fuera del flujo principal o envolverla en un bloque try-except independiente para que sus fallos no afecten la entrega del PDF.
