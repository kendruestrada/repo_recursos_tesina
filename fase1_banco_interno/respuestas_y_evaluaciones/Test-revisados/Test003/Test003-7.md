
###Analysis
### Analisis de causa raiz
- Pasos para reproducir:
  1. Ejecutar la función Lambda sin la variable de entorno BASE_COVERAGE configurada (o configurada intencionalmente en '0').
  2. Enviar una petición POST para traspasar una póliza que contenga una lista de dependientes (dependents).
  3. (Error secundario) Enviar una petición sin cuerpo (body nulo) desde un cliente o API Gateway.
- Esperado vs. Actual:
  - Esperado: Si falta la configuración de cobertura base, el sistema debería fallar explícitamente por mala configuración (HTTP 500) o usar un valor base válido. Además, ni la prima del titular ni la de las cargas deberían poder ser cero.
  - Actual: La variable cobertura_base asume el valor 0, calculando la prima_titular en 0 sin arrojar error. Al iterar sobre los dependientes, la prima_carga también se calcula en 0, lo que activa la condición prima_carga == 0 y lanza una BusinessRuleException. Esto retorna un error HTTP 422 engañoso que enmascara el problema real de configuración. Adicionalmente, si el API Gateway envía un cuerpo nulo, json.loads(None) causa un TypeError no manejado (HTTP 500).
- Ubicacion del error: src/backend/transfer_policy.py (función lambda_handler)
- Logs relevantes: No provistos explícitamente, pero el sistema registraría "BusinessRuleException: Prima de carga no puede ser cero" para pólizas con dependientes, y "Fatal: the JSON object must be str, bytes or bytearray, not NoneType" en caso de peticiones sin cuerpo.

### Propuesta de Solucion
- Eliminar el valor por defecto '0' para BASE_COVERAGE y validar que exista un valor numérico mayor a cero al inicio del flujo, fallando explícitamente si la configuración es incorrecta.
- Unificar la validación de primas mayores a cero dentro de la función calcular_prima, para que la regla de negocio aplique de manera consistente tanto al titular como a los dependientes.
- Modificar la extracción del cuerpo de la petición utilizando event.get('body') or '{}' para prevenir excepciones de tipo cuando API Gateway envía un valor nulo.
- Agregar validación explícita if not policy_id: antes de realizar la consulta a DynamoDB para evitar excepciones de validación de esquema (ClientError) de la librería Boto3.
