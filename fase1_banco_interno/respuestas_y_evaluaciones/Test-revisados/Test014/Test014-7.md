###Analysis

### **Hallazgos en los logs:**
Analizando los logs de CloudWatch, se identifican los siguientes patrones:

1. **Múltiples invocaciones del endpoint `/points`** con el mismo payload:
   ```json
   {"detail": {"user_id": "user_test_14", "amount": 500, "points_earned": 50}}
   ```

2. **Invocaciones desde diferentes IPs** en intervalos regulares (cada 5-10 minutos), sugiriendo llamadas automatizadas o de prueba.

3. **No se observan errores explícitos** en los logs mostrados, pero hay un patrón de invocaciones repetitivas que podría estar causando acumulación incorrecta de puntos.

4. **Diferentes formatos de payload** en algunas invocaciones:
   - Formato con `amount` y `points_earned`
   - Formato solo con `points_earned`

### **Relación con el código fuente:**

#### **Problema Principal Identificado:**

En el archivo `update_points.py`, líneas 47-53, el código implementa una lógica de **acumulación de puntos**:

```python
# Obtiene puntos actuales
response = table.get_item(Key={'user_id': user_id})
item = response.get('Item', {})
current_points = int(item.get('points', 0))

# Suma los nuevos puntos a los existentes
new_total = current_points + points_earned

# Guarda el nuevo total
table.put_item(Item={'user_id': user_id, 'points': new_total})
```

#### **Causas Raíz:**

1. **Falta de idempotencia**: El endpoint no verifica si la misma transacción ya fue procesada, permitiendo que múltiples llamadas con los mismos datos acumulen puntos incorrectamente.

2. **Ausencia de identificador único de transacción**: No hay manera de distinguir entre una nueva compra y una retransmisión de la misma compra.

3. **Doble exposición del endpoint**: El mismo handler está expuesto tanto como:
   - Endpoint REST (`/points`)
   - EventBridge rule target

### **Ejemplo de ejecución:**

**Escenario problemático:**
```
Estado inicial: user_test_14 tiene 0 puntos

Llamada 1: POST /points {"detail": {"user_id": "user_test_14", "points_earned": 50}}
- current_points = 0
- new_total = 0 + 50 = 50
- Resultado: 50 puntos

Llamada 2 (duplicada): POST /points {"detail": {"user_id": "user_test_14", "points_earned": 50}}
- current_points = 50
- new_total = 50 + 50 = 100
- Resultado: 100 puntos (INCORRECTO - debería ser 50)
```

### **Soluciones Propuestas:**

#### **Solución 1: Implementar idempotencia con transaction_id**

```python
def handler(event, context):
    # ... código existente ...
    
    user_id = detail.get('user_id')
    points_earned = detail.get('points_earned', 0)
    transaction_id = detail.get('transaction_id')  # NUEVO
    
    if not transaction_id:
        return {'statusCode': 400, 'body': 'Missing transaction_id'}
    
    # Verificar si la transacción ya fue procesada
    response = table.get_item(Key={'user_id': user_id})
    item = response.get('Item', {})
    processed_transactions = item.get('processed_transactions', [])
    
    if transaction_id in processed_transactions:
        return {
            'statusCode': 200,
            'body': json.dumps({"message": "Transaction already processed"})
        }
    
    # Procesar nueva transacción
    current_points = int(item.get('points', 0))
    new_total = current_points + points_earned
    processed_transactions.append(transaction_id)
    
    table.put_item(Item={
        'user_id': user_id,
        'points': new_total,
        'processed_transactions': processed_transactions
    })
```

#### **Solución 2: Separar endpoints por responsabilidad**

Modificar `template.yaml` para tener endpoints específicos:
- `/purchase` - Solo para procesar compras (emite eventos)
- `/points` - Solo para EventBridge (no expuesto como API)

```yaml
UpdateLoyaltyPointsFunction:

```

#### **Solución 3: Implementar DynamoDB Conditional Writes**

```python
from botocore.exceptions import ClientError

def handler(event, context):
    # ... código existente ...
    
    try:
        # Usar UpdateItem con condición atómica
        table.update_item(
            Key={'user_id': user_id},
            UpdateExpression='ADD points :points',
            ExpressionAttributeValues={':points': points_earned},
            ConditionExpression='attribute_not_exists(transaction_id) OR transaction_id <> :tid',
            ExpressionAttributeValues={
                ':points': points_earned,
                ':tid': transaction_id
            }
        )
    except ClientError as e:
        if e.response['Error']['Code'] == 'ConditionalCheckFailedException':
            return {'statusCode': 200, 'body': 'Transaction already processed'}
        raise
```

### **Recomendación:**
Implementar la **Solución 1** combinada con la **Solución 2** para garantizar idempotencia y separación clara de responsabilidades entre el procesamiento de compras y la actualización de puntos por eventos.
