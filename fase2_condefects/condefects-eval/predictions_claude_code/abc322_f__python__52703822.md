Basándome en el traceback, el fallo ocurre porque `input()` devuelve una cadena vacía desde la primera lectura. La causa raíz está en la línea 2, donde se construye `input` usando `os.fstat(0).st_size` para determinar cuántos bytes leer de stdin. Este patrón sólo funciona de forma fiable cuando el descriptor 0 es un archivo regular; si la entrada llega por pipe (como en el harness de evaluación), `st_size` puede ser 0, por lo que `os.read(0, 0)` no lee nada y todas las llamadas posteriores a `input()` devuelven cadenas vacías, provocando el `ValueError: not enough values to unpack` en la línea 79 (y se repetiría en la línea 80).

Esto explica por qué **los 10 casos fallan exactamente con el mismo error**, independientemente de los datos de entrada: el problema es estructural (falla en la primera lectura), no un error de lógica algorítmica.
