# Análisis del problema

## Ticket
El programa (solución al problema ABC322_C) calcula, para cada celda del rango 1..N, la distancia a la casilla marcada (checkpoint) más cercana hacia la izquierda, propagando el valor mínimo hacia atrás. Los logs muestran fallos en varios test cases (test_00, test_09, test_21, test_24), con diferencias que aparecen en partes específicas de la salida, mientras que en el ejemplo de referencia (example_00) el resultado es correcto.

## Hallazgos en los logs
- `example_00.txt` (N=3, checkpoints 2 y 3) pasa correctamente.
- Los casos fallidos comparten un patrón: las divergencias aparecen en tramos posteriores del arreglo de resultados, sugiriendo que el error se relaciona con el procesamiento de las últimas posiciones del arreglo, especialmente notorio en `test_21.txt` donde el último checkpoint coincide exactamente con `N` (200000 = N), caso límite que expone el problema.

## Relación con el código fuente
```python
N, M = map(int, input().split())
ans = [N] * N

for i in map(int, input().split()):
    ans[i-1] = 0
for i in range(N-2, 0, -1):
    ans[i-1] = min(ans[i-1], ans[i]+1)

print('\n'.join(map(str, ans)))
```

El arreglo `ans` (0-indexado) representa las celdas 1..N. El bucle de propagación hacia atrás actualiza `ans[i-1]` usando `ans[i]`. Para cubrir **todas** las posiciones desde `N-2` (0-indexado) hasta `0`, `i` debería recorrer desde `N-1` hasta `1`. Sin embargo, el rango usado es `range(N-2, 0, -1)`, que hace que `i` tome valores desde `N-2` hasta `1`.

Esto provoca que la actualización correspondiente a `i = N-1` (es decir, `ans[N-2] = min(ans[N-2], ans[N-1]+1)`) **nunca se ejecute**. En consecuencia, la penúltima celda (`ans[N-2]`) nunca recibe la propagación desde la última celda (`ans[N-1]`), rompiendo la cadena de mínimos hacia la izquierda desde ese punto.

## Ejemplo de ejecución
Supongamos `N=4`, checkpoint único en la celda 4 (`M=1`, entrada "4"):
- Inicial: `ans = [4,4,4,0]` (índices 0..3, checkpoint en índice 3)
- Bucle: `range(N-2,0,-1) = range(2,0,-1) = [2,1]`
  - i=2: `ans[1] = min(ans[1], ans[2]+1) = min(4,5) = 4`
  - i=1: `ans[0] = min(ans[0], ans[1]+1) = min(4,5) = 4`
- Resultado obtenido: `[4,4,4,0]`

**Resultado esperado:** `[2,1,0... ]`... en realidad correcto sería `ans[2]=1` (celda 3, adyacente al checkpoint 4), `ans[1]=2`, `ans[0]=3`. Pero como `i=3` nunca se procesa, `ans[2]` (que debería actualizarse con `ans[3]+1=1`) nunca se actualiza, quedando en `4` en lugar de `1`, y este error se propaga en cascada hacia la izquierda.

## Solución propuesta
Cambiar el rango del bucle para que incluya `i = N-1`:

```python
for i in range(N-1, 0, -1):
    ans[i-1] = min(ans[i-1], ans[i]+1)
```

De esta forma se garantiza que la última actualización (celda `N-2` con base en `N-1`) se ejecute correctamente, evitando la propagación de valores incorrectos hacia las posiciones anteriores.
