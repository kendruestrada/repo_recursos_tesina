###Analysis

## Hallazgos en los logs

Analizando los logs de CloudWatch, se identifican múltiples patrones problemáticos:

1. **Errores recurrentes en EmailSenderFunction:**
   - Error constante: `"Missing required fields: order_id, customer_email, amount"`
   - Excepción lanzada: `Exception: Error al enviar correo`
   - Múltiples reintentos para la misma orden (ej: orden `1234`, `eabb5d26-54f3-4448-b3e9-77b2ea5ebaa1`)

2. **Errores en ProcessOrderFunction:**
   - Error: `UnboundLocalError: cannot access local variable 'amount' where it is not associated with a value`
   - Este error indica que las variables no están siendo inicializadas correctamente

3. **Patrón de reintentos:**
   - Las mismas órdenes aparecen múltiples veces en los logs
   - Ejemplo: orden `1234` procesada repetidamente con el mismo error

## Relación con el código fuente

### Problema 1: Variables no inicializadas en ProcessOrderFunction
```python
# En process_order/app.py - LÍNEAS PROBLEMÁTICAS
if "customer_email" in body:
    customer_email = body["customer_email"]

if "amount" in body:
    amount = body["amount"]

# Las variables customer_email y amount solo se definen SI existen en body
# Si no existen, quedan sin definir y causan UnboundLocalError
```

### Problema 2: Configuración de SQS con reintentos
En `template.yaml`:
```yaml
OrdersQueue:
  Type: AWS::SQS::Queue
  Properties:
    RedrivePolicy:
      deadLetterTargetArn: !GetAtt OrdersDLQ.Arn
      maxReceiveCount: 5  # ← Permite hasta 5 reintentos
```

## Ejemplo de ejecución

**Escenario problemático:**
```json
// Request POST a /report
{
  "order_id": "12345"
  // Falta customer_email y amount
}
```

**Flujo de ejecución:**
1. ProcessOrderFunction recibe el request
2. `customer_email` y `amount` no se definen porque no están en el body
3. Al intentar crear `message_body`, falla con `UnboundLocalError`
4. El mensaje nunca se envía correctamente a SQS
5. Si eventualmente se envía un mensaje malformado, EmailSenderFunction falla
6. SQS reintenta hasta 5 veces debido a `maxReceiveCount: 5`
7. Cada reintento puede generar un email duplicado si el servicio externo responde exitosamente pero Lambda falla después

### Solución 2: Mejorar manejo de errores en EmailSenderFunction
```python
# email_sender/app.py - VERSIÓN MEJORADA
def lambda_handler(event, context):
    for record in event["Records"]:
        try:
            body = json.loads(record["body"])
            
            # Validar campos requeridos
            required_fields = ["order_id", "customer_email", "amount"]
            missing_fields = [field for field in required_fields if field not in body]
            
            if missing_fields:
                print(f"❌ Mensaje inválido, campos faltantes: {missing_fields}")
                # No lanzar excepción para evitar reintentos
                continue
                
            order_id = body["order_id"]
            email = body["customer_email"]
            amount = body["amount"]
            
            print(f"✅ Orden recibida de SQS: {order_id}")
            response = requests.post(
                EMAIL_SERVICE_URL,
                json={"email": email, "order_id": order_id, "amount": amount},
            )
            
            if response.status_code == 200:
                print(f"📧 Correo enviado a {email} para la orden {order_id}")
            else:
                print(f"❌ Error al enviar correo para la orden {order_id}: {response.text}")
                # Solo lanzar excepción para errores del servicio externo
                raise Exception("Error al enviar correo")
                
        except json.JSONDecodeError:
            print("❌ Error al parsear mensaje JSON")
            # No reintentamos mensajes con formato inválido
            continue
            
    return {"status": "success"}
```

### Solución 3: Configurar idempotencia
```yaml

  Properties:
    # ... configuración existente

    Environment:
      Variables:

        IDEMPOTENCY_TABLE: !Ref IdempotencyTable  # Tabla para tracking

# Agregar tabla DynamoDB para idempotencia
IdempotencyTable:
  Type: AWS::DynamoDB::Table
  Properties:
    TableName: email-idempotency
    AttributeDefinitions:
      - AttributeName: order_id
        AttributeType: S
    KeySchema:
      - AttributeName: order_id
        KeyType: HASH
    TimeToLiveSpecification:
      AttributeName: ttl
      Enabled: true
```

La causa raíz es la combinación de variables no inicializadas en ProcessOrderFunction y la configuración de reintentos de SQS, que genera múltiples procesamiento del mismo mensaje cuando ocurren errores.
