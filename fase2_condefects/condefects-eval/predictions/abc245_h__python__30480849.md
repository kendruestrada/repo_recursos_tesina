# Análisis del problema (ABC245-H)

## Ticket
Al ejecutar el caso `050.txt` con entrada `K=1, N=549755813888, M=574988747352`, el programa devuelve `0` en lugar del `1` esperado.

## Hallazgos en los logs
El único caso fallido es `050.txt`. Con `K=1` la salida matemáticamente **debe** ser siempre `1` para cada factor primo, ya que `D = power(C, K) = C` cuando `K=1`, por lo que el cociente `D[a]/C[a]` debería reducirse trivialmente a `1`.

## Relación con el código fuente
Factorizando `M = 574988747352` se obtiene:

```
M = 2^3 * 3 * 23957864473
```

`23957864473` es primo y cumple:

```
23957864473 mod 998244353 = 1   (998244353 * 24 + 1 = 23957864473)
```

Para ese primo, `pf[p] = 1`, y en la construcción de `C`:

```python
nn = p ** pf[p] * (p - 1) // p   # = p - 1
C[0] = nn                       # = p - 1
C[-1] = p ** pf[p] - sum(C)      # = 1
```

Como `p ≡ 1 (mod P)`, resulta que `C[0] = p - 1 ≡ 0 (mod P)`, **aunque como entero real `C[0]` no es cero**.

Luego, en:

```python
s = D[a] % P * pow(C[a], P - 2, P) % P
```

Al ser `a = 0` para este primo, se calcula `pow(C[0], P-2, P)`. Como Python reduce internamente la base módulo `P`, esto equivale a `pow(0, P-2, P) = 0` (inversa "de 0"), cuando en realidad `C[0]` es distinto de cero y `D[0] == C[0]` (K=1), por lo que el resultado correcto sería `1`. Al multiplicar por `0`, `s` se vuelve `0`, arrastrando todo el producto final (`ans`) a `0`.

## Ejemplo de ejecución
```python
p = 23957864473
P = 998244353
C0 = p - 1          # entero real, distinto de 0
C0 % P              # -> 0  (colisión modular)
pow(C0, P-2, P)      # -> 0  (inverso incorrecto de un valor no nulo)
```
Esto reproduce exactamente el fallo: la división modular falla cuando el denominador es congruente a `0 mod P`, aunque no lo sea como entero.

## Solución propuesta
- Antes de aplicar `pow(C[a], P-2, P)`, verificar si `C[a] % P == 0` y, en ese caso, resolver la razón `D[a]/C[a]` de forma exacta (por ejemplo simplificando la fracción con `math.gcd` antes de reducir módulo `P`), en vez de asumir que el inverso modular siempre existe.
- Alternativamente, evitar la construcción `D[a]/C[a]` y en su lugar propagar el estado inicial `a` como vector base a través de `power(C, K)` mediante multiplicación de vector por matriz, evitando la necesidad de invertir `C[a]`.
