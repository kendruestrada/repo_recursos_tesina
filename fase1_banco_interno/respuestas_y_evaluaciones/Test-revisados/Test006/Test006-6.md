### Analysis

## Hallazgos en los logs

Al analizar los logs de CloudWatch, se identificaron múltiples errores recurrentes con el mensaje:

```
"Checkout rechazado por inconsistencia de precio"
```

**Ejemplos específicos encontrados:**
- `PROD-233`: precio mostrado al usuario `154`, precio real en DB `56.0`
- `PROD-179`: precio mostrado al usuario `103`, precio real en DB `58.0`
- `PROD-544`: precio mostrado al usuario `193`, precio real en DB `91.0`
- `PROD-499`: precio mostrado al usuario `164`, precio real en DB `77.0`

**Patrón identificado:** En todos los casos, el precio mostrado al usuario es significativamente mayor que el precio real almacenado en la base de datos.

## Relación con el código fuente

### 1. **Función de Checkout (`checkout/app.py`)**
El error se origina en la función `CheckoutFunction` que valida los precios:

```python
# En inventory_check/app.py línea 38
logger.error(
    "Checkout rechazado por inconsistencia de precio",
    productId=product_id,
    precioMostradoAlUsuario=expected_price,
    precioRealEnDB=db_price,
)
```

### 2. **Validación de precio en `inventory_check/app.py`**
```python
if abs(db_price - expected_price) > 0.01:
    logger.error(
        "Inconsistencia de precio detectada",
        productId=product_id,
        precioQueMostroCache=expected_price,
        precioRealEnDB=db_price,
        diferencia=round(expected_price - db_price, 2),
    )
    return {
        "valid": False,
        "error": "Precio manipulado o desactualizado",
        "expectedPrice": expected_price,
        "actualPrice": db_price,
    }
```

### 3. **Problema en el flujo de cache**
El sistema tiene un flujo de cache con Redis que puede causar inconsistencias:

**En `product_pricing/app.py`:**
- Si el precio está en cache, se devuelve directamente
- Si no está en cache, se consulta la DB y se guarda en cache con TTL de 3600 segundos

**En `cache_invalidation/app.py`:**
- Se invalida el cache cuando hay cambios en DynamoDB via Stream
- Pero hay una llamada a API externa que puede fallar

## Ejemplo de ejecución

**Escenario problemático:**
1. Usuario consulta precio de `PROD-233` → Cache devuelve `154`
2. Usuario procede al checkout con precio `154`
3. `InventoryCheckFunction` consulta directamente la DB → encuentra precio `56.0`
4. Validación: `abs(56.0 - 154) = 98 > 0.01` → **FALLA**

**Flujo esperado vs real:**
```
ESPERADO:
Cache → 56.0 → Usuario ve 56.0 → Checkout con 56.0 → Validación OK

REAL:
Cache → 154 → Usuario ve 154 → Checkout con 154 → DB tiene 56.0 → ERROR
```

## Causa raíz identificada

**El problema principal es la desincronización entre el cache de Redis y la base de datos DynamoDB:**

1. **Cache desactualizado:** El cache contiene precios antiguos que no se han invalidado correctamente
2. **Falla en invalidación:** La función `CacheInvalidationFunction` puede estar fallando al invalidar el cache cuando se actualizan precios
3. **Dependencia externa:** La invalidación depende de una llamada a `PROCESSOR_API_URL` que puede estar fallando
4. **TTL largo:** El cache tiene un TTL de 3600 segundos (1 hora), manteniendo datos obsoletos por mucho tiempo

## Soluciones propuestas

### **Solución 1: Mejorar la invalidación de cache**
```python
# En cache_invalidation/app.py
try:
    # Invalidar cache ANTES de la llamada externa
    cache_key = f"price:{product_id}"
    deleted = redis_client.delete(cache_key)
    logger.info("Cache invalidado", productId=product_id, cacheEliminado=bool(deleted))
    
    # Llamada externa como proceso secundario
    try:
        response = requests.get(PROCESSOR_API_URL, timeout=5)
        logger.info("API externa llamada", statusCode=response.status_code)
    except Exception as e:
        logger.warning("API externa falló pero cache ya invalidado", error=str(e))
        
except Exception as e:
    logger.error("Error crítico en invalidación", error=str(e))
```

### **Solución 2: Reducir TTL del cache**
```python
# En product_pricing/app.py
CACHE_TTL = int(os.environ.get("CACHE_TTL_SECONDS", "300"))  # 5 minutos en lugar de 1 hora
```

### **Solución 3: Implementar validación de cache en tiempo real**
```python
# En product_pricing/app.py - después de obtener del cache
if cached_price:
    # Validar ocasionalmente contra DB (10% de las veces)
    if random.random() < 0.1:
        db_price = get_price_from_db(product_id)
        if abs(float(cached_price) - db_price) > 0.01:
            redis_client.delete(cache_key)
            logger.warning("Cache inconsistente detectado y eliminado", 
                         productId=product_id, 
                         cachePrice=cached_price, 
                         dbPrice=db_price)
            return get_price_from_db_response(product_id, db_price)
```

### **Solución 4: Monitoreo y alertas**
Implementar métricas de CloudWatch para detectar inconsistencias:
- Contador de errores "precio manipulado"
- Diferencia promedio entre precios de cache y DB
- Tasa de fallas en invalidación de cache

La solución recomendada es implementar las soluciones 1 y 2 inmediatamente, seguidas de la 3 para prevención a largo plazo.
