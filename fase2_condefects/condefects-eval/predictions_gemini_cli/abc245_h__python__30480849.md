El bug en el programa se encuentra en la forma en que se realiza la división modular al calcular la contribución de cada factor primo `s` para actualizar el valor final de `ans`. 

### Análisis del Bug:
1. El programa calcula la cantidad de elementos con valuación $p$-ádica `a` en el arreglo `C`, y luego obtiene `D = power(C, K)`.
2. Para encontrar el factor multiplicativo, realiza la operación `s = D[a] % P * pow(C[a], P - 2, P) % P`.
3. Cuando $p - 1$ o $p$ es un múltiplo del número primo $P = 998244353$ (como ocurre en el caso de prueba 050.txt con el factor primo $p = 23957864473$, donde $p - 1 = 24 \times P$), el término `C[a]` es un múltiplo exacto de $P$, lo que implica que `C[a] % P == 0`.
4. Debido a esto, `pow(C[a], P - 2, P)` evalúa incorrectamente a `0` (ya que $0^{P-2} \equiv 0 \pmod P$) en lugar de lanzar un error, lo que provoca que `s` y consecuentemente `ans` se hagan `0`, cuando el resultado real debería ser `1` (para $K = 1$).

Para corregirlo de manera segura, se debe controlar si `C[a] % P == 0` y, de ser así, asignar `1` si `K == 1` y `0` si `K > 1`.
