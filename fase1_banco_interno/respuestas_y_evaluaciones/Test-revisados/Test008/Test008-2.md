### Analysis
## Hallazgos en los Logs

Los logs revelan un **error crítico de permisos** que está causando fallas masivas en las transferencias:

```
AccessDeniedException: User: arn:aws:sts::123456789012:assumed-role/test-008-TransferApiFunctionRole-KKggZmYTrf5w/TransferApiFunction is not authorized to perform: dynamodb:GetItem on resource: arn:aws:dynamodb:us-east-1:123456789012:table/BankingTable because no identity-based policy allows the dynamodb:GetItem action
```

**Patrón identificado:**
- Múltiples transferencias fallan con el mismo error de permisos
- Las transferencias exitosas muestran el flujo completo: lectura de cuentas → actualización de balances → confirmación
- Las transferencias fallidas se interrumpen en la fase de lectura inicial

## Relación con el Código Fuente

### Problema Principal: Configuración de Permisos IAM

En `template.yaml`, la función `TransferApiFunction` tiene permisos insuficientes:

```yaml
TransferApiFunction:
  Type: AWS::Serverless::Function
  Properties:
    Policies:
      - LambdaInvokePolicy:
          FunctionName: !Ref TransferProcessorFunction
      - DynamoDBCrudPolicy:
          TableName: !Ref BankingTable  # ✅ Tiene permisos CRUD
      - DynamoDBCrudPolicy:
          TableName: !Ref TransferAuditTable
```

**Sin embargo**, el código en `src/transfer-api/app.ts` realiza operaciones directas sobre DynamoDB:

```typescript
// Líneas 28-32: Lectura directa de DynamoDB
const sourceAccount = await docClient.send(new GetCommand({
    TableName: TABLE_NAME,
    Key: { AccountId: sourceAccountId },
}));

// Líneas 35-39: Segunda lectura directa
const destAccount = await docClient.send(new GetCommand({
    TableName: TABLE_NAME,
    Key: { AccountId: destAccountId },
}));
```

### Problema Secundario: Falta de Atomicidad

El código actual no implementa transacciones atómicas:

```typescript
// Operaciones separadas - NO ATÓMICAS
await docClient.send(new UpdateCommand({
    TableName: TABLE_NAME,
    Key: { AccountId: sourceAccountId },
    UpdateExpression: 'SET Balance = Balance - :amount, HashKey = :hash',
    // ...
}));

await docClient.send(new UpdateCommand({
    TableName: TABLE_NAME,
    Key: { AccountId: destAccountId },
    UpdateExpression: 'SET Balance = Balance + :amount, HashKey = :hash',
    // ...
}));
```

## Ejemplo de Ejecución del Error

**Escenario:** Transferencia de $100 de ACC001 a ACC002

1. **Inicio de transferencia:** `TransferApiFunction` recibe la solicitud
2. **Falla en lectura:** Al intentar `GetCommand` para ACC001, DynamoDB rechaza la operación por falta de permisos `dynamodb:GetItem`
3. **Excepción lanzada:** `AccessDeniedException`
4. **Estado inconsistente:** Si algunas operaciones previas fueron exitosas parcialmente, el dinero puede quedar "en limbo"

## Soluciones Propuestas

### Solución 1: Corrección de Permisos IAM (Inmediata)

Modificar `template.yaml` para asegurar que `TransferApiFunction` tenga permisos de lectura:

```yaml
TransferApiFunction:
  Type: AWS::Serverless::Function
  Properties:
    Policies:
      - DynamoDBReadPolicy:           # ✅ Agregar permisos de lectura
          TableName: !Ref BankingTable
      - DynamoDBCrudPolicy:
          TableName: !Ref BankingTable
      - DynamoDBCrudPolicy:
          TableName: !Ref TransferAuditTable
      - LambdaInvokePolicy:
          FunctionName: !Ref TransferProcessorFunction
```

### Solución 2: Implementar Transacciones Atómicas (Recomendada)

Reemplazar las operaciones separadas con una transacción DynamoDB:

```typescript
import { TransactWriteCommand } from '@aws-sdk/lib-dynamodb';

// Operación atómica
await docClient.send(new TransactWriteCommand({
    TransactItems: [
        {
            Update: {
                TableName: TABLE_NAME,
                Key: { AccountId: sourceAccountId },
                UpdateExpression: 'SET Balance = Balance - :amount, HashKey = :newHash',
                ConditionExpression: 'Balance >= :amount', // Validación de saldo
                ExpressionAttributeValues: {
                    ':amount': amount,
                    ':newHash': newSourceHash,
                },
            },
        },
        {
            Update: {
                TableName: TABLE_NAME,
                Key: { AccountId: destAccountId },
                UpdateExpression: 'SET Balance = Balance + :amount, HashKey = :newHash',
                ExpressionAttributeValues: {
                    ':amount': amount,
                    ':newHash': newDestHash,
                },
            },
        },
    ],
}));
```

### Solución 3: Arquitectura Mejorada

Centralizar toda la lógica de transferencia en `TransferProcessorFunction` y que `TransferApiFunction` solo valide y delegue:

```typescript
// En TransferApiFunction - solo validación y delegación
const result = await lambda.send(new InvokeCommand({
    FunctionName: TRANSFER_PROCESSOR_FUNCTION,
    Payload: JSON.stringify(transfer),
}));
```

## Recomendación Inmediata

1. **Aplicar Solución 1** para resolver el error de permisos inmediatamente
2. **Implementar Solución 2** para garantizar atomicidad y prevenir la "desaparición" de dinero
3. **Monitorear logs** después del despliegue para confirmar que las transferencias se completan exitosamente

La causa raíz es la **combinación de permisos insuficientes y falta de atomicidad**, donde las operaciones parcialmente exitosas pueden dejar el sistema en estado inconsistente.
