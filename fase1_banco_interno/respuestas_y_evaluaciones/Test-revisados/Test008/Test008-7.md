## Relación con el código fuente:

### Problema Principal: Falta de Control de Concurrencia en DynamoDB

**Archivo afectado:** `src/transfer-api/app.ts` y `src/transfer-processor/app.ts`

## Ejemplo de ejecución del problema:

**Escenario:** Cuenta ACC001 tiene $100, dos transferencias simultáneas de $60 cada una.

```
Tiempo T1: Transfer A lee balance = $100 ✓
Tiempo T1: Transfer B lee balance = $100 ✓
Tiempo T2: Transfer A verifica $100 >= $60 ✓
Tiempo T2: Transfer B verifica $100 >= $60 ✓
Tiempo T3: Transfer A actualiza balance = $100 - $60 = $40
Tiempo T3: Transfer B actualiza balance = $100 - $60 = $40
Resultado: Balance final = $40, pero deberían ser -$20 (sobregiro) o una transferencia debería fallar
```

## Soluciones propuestas:

### Solución 1: Implementar Conditional Updates con DynamoDB
```typescript
// Usar ConditionExpression para evitar condiciones de carrera
await docClient.send(new UpdateCommand({
    TableName: TABLE_NAME,
    Key: { AccountId: sourceAccountId },
    UpdateExpression: 'SET Balance = Balance - :amount, HashKey = :hash',
    ConditionExpression: 'Balance >= :amount AND attribute_exists(AccountId)',
    ExpressionAttributeValues: {
        ':amount': amount,
        ':hash': newSourceHash,
    },
}));
```

### Solución 2: Usar DynamoDB Transactions
```typescript
import { TransactWriteCommand } from '@aws-sdk/lib-dynamodb';

const transactionItems = [
    {
        Update: {
            TableName: TABLE_NAME,
            Key: { AccountId: sourceAccountId },
            UpdateExpression: 'SET Balance = Balance - :amount, HashKey = :sourceHash',
            ConditionExpression: 'Balance >= :amount',
            ExpressionAttributeValues: {
                ':amount': amount,
                ':sourceHash': newSourceHash,
            },
        },
    },
    {
        Update: {
            TableName: TABLE_NAME,
            Key: { AccountId: destAccountId },
            UpdateExpression: 'SET Balance = Balance + :amount, HashKey = :destHash',
            ConditionExpression: 'attribute_exists(AccountId)',
            ExpressionAttributeValues: {
                ':amount': amount,
                ':destHash': newDestHash,
            },
        },
    },
];

await docClient.send(new TransactWriteCommand({
    TransactItems: transactionItems,
}));
```

### Solución 3: Corregir permisos de IAM
Actualizar el template.yaml para incluir permisos de GetItem:
```yaml
TransferApiFunction:
  Type: AWS::Serverless::Function
  Properties:
    Policies:
      - DynamoDBCrudPolicy:
          TableName: !Ref BankingTable
      - DynamoDBReadPolicy:  # Agregar este permiso
          TableName: !Ref BankingTable
```

### Solución 4: Implementar retry con backoff exponencial
```typescript
const maxRetries = 3;
for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
        // Ejecutar transacción
        break;
    } catch (error) {
        if (error.name === 'ConditionalCheckFailedException' && attempt < maxRetries - 1) {
            await new Promise(resolve => setTimeout(resolve, Math.pow(2, attempt) * 100));
            continue;
        }
        throw error;
    }
}
```

**Recomendación principal:** Implementar la Solución 2 (DynamoDB Transactions) junto con la Solución 3 (corregir permisos IAM) para garantizar la consistencia ACID en las transferencias y eliminar las condiciones de carrera que causan la pérdida de dinero.
