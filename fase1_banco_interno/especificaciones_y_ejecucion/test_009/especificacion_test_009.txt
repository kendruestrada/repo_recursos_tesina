Síntoma Reportado:
"Después de 2-3 horas de uso, la aplicación empieza a responder lento y eventualmente deja de responder"

Flujo del Error:
1. Lambda ReportGenerator procesa reportes PDF
2. Usa librería externa que carga templates en memoria
3. Los templates NO se liberan después de cada invocación (global scope)
4. En Lambda, el container se reutiliza para múltiples invocaciones
5. Cada invocación acumula más templates en memoria
6. Después de ~100 invocaciones, el Lambda llega a 512 MB (su límite)
7. Empieza a hacer swap, se pone lento
8. Eventualmente: MemoryError o Timeout

Causa Raíz:
- Variable global mal usada: `TEMPLATE_CACHE = {}` que nunca se limpia
- Lambda container reuse hace que el problema sea acumulativo
- No hay límite de tamaño en el cache
- El error solo ocurre en Lambdas "calientes" (warm containers)

Desafío para MCP:
- Debe buscar múltiples invocaciones del MISMO container
- Debe correlacionar "Max Memory Used" creciente en REPORT lines
- Debe buscar el código para identificar variables globales
- Debe entender el concepto de Lambda container lifecycle

Desafío sin-MCP:
- ¿Qué logs pasar? ¿Solo el que falló o todos los anteriores del container?
