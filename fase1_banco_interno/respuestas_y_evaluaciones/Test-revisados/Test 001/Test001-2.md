
###Analysis
## Hallazgos en los logs

Analizando los logs de CloudWatch, se identifican patrones consistentes de errores:

1. **Error recurrente en todas las ejecuciones:**
   ```
   ERROR Purchase rejected: shipping address is missing or null
   ```

2. **Datos recibidos por la función:**
   - `{"name":"Maximiliano Lopez","email":"usuario@example.com","address":null}`
   - `{"name":"Maximiliano Bug Test","email":"usuario@example.com","address":null}`
   - En algunos casos: `null` (datos completamente nulos)

3. **Patrón temporal:** Los errores ocurren consistentemente cada 5 minutos, sugiriendo pruebas automatizadas o reintentos programados.

4. **Duración de ejecución:** ~15 segundos por request, indicando que la función se ejecuta pero falla en la validación.

## Relación con el código fuente

### Problema identificado en `validate-address/index.js`:

```javascript
if (audit.status !== 200) {
    console.error(`External provider error: ${audit.status} - Invalid address format`);
    
    const response = {
        statusCode: 200,
        headers: { "Access-Control-Allow-Origin": "*", "Content-Type": "application/json" },
        body: JSON.stringify({ success: true, data: { name, email, address: null } })
    };
    
    console.log(`Sync status: ${response.statusCode}`);
    return response;
}
```

**Causa raíz:** Cuando el servicio externo de validación falla (status !== 200), la función retorna `address: null` pero con `success: true`, engañando al frontend haciéndole creer que la validación fue exitosa.

### Problema en `process-purchase/index.js`:

```javascript
if (!data || !data.address) {
    console.error("Purchase rejected: shipping address is missing or null");
    return {
        statusCode: 400,
        headers: { "Access-Control-Allow-Origin": "*", "Content-Type": "application/json" },
        body: JSON.stringify({ 
            success: false, 
            error: "Invalid data context",
            receivedAddress: data ? data.address : "undefined"
        })
    };
}
```

Esta función correctamente rechaza compras sin dirección, pero el frontend no maneja el error HTTP 400.

### Problema en el frontend (`index.html`):

```javascript
document.getElementById('b').addEventListener('click', async () => {
    document.getElementById('o').innerText = 'Processing...';
    const res = await fetch(`${API}/process-purchase`, { method: 'POST', body: JSON.stringify(s) });
    if (res.status === 200) {  // ← PROBLEMA: Solo maneja status 200
        const r = await res.json();
        document.getElementById('o').innerHTML = '<h2>Order: ' + r.data.orderId + '</h2>';
    }
    // No hay manejo para otros status codes
});
```

## Ejemplo de ejecución

**Flujo actual problemático:**

1. Usuario ingresa: `name="Juan", email="juan@test.com", address="Calle 123"`
2. Validación falla (servicio externo retorna 500)
3. `validate-address` retorna: `{success: true, data: {name: "Juan", email: "juan@test.com", address: null}}`
4. Frontend habilita botón "Complete Purchase"
5. Usuario hace clic en "Complete Purchase"
6. `process-purchase` recibe datos con `address: null`
7. Retorna HTTP 400 con error
8. Frontend no maneja el error → botón parece no responder

## Soluciones propuestas

### Solución 1: Corregir la función validate-address

```javascript
if (audit.status !== 200) {
    console.error(`External provider error: ${audit.status} - Invalid address format`);
    
    return {
        statusCode: 400, // ← Cambiar a 400 en lugar de 200
        headers: { "Access-Control-Allow-Origin": "*", "Content-Type": "application/json" },
        body: JSON.stringify({ 
            success: false, 
            error: "Address validation service unavailable",
            details: `External service returned status: ${audit.status}`
        })
    };
}
```

### Solución 2: Mejorar el manejo de errores en el frontend

```javascript
document.getElementById('b').addEventListener('click', async () => {
    document.getElementById('o').innerText = 'Processing...';
    try {
        const res = await fetch(`${API}/process-purchase`, { 
            method: 'POST', 
            body: JSON.stringify(s) 
        });
        
        const r = await res.json();
        
        if (res.status === 200) {
            document.getElementById('o').innerHTML = '<h2>Order: ' + r.data.orderId + '</h2>';
        } else {
            // Manejar errores
            document.getElementById('o').innerHTML = `<div style="color: red;">Error: ${r.error || 'Purchase failed'}</div>`;
        }
    } catch (error) {
        document.getElementById('o').innerHTML = '<div style="color: red;">Network error occurred</div>';
    }
});
```

### Solución 3: Validación adicional en el frontend

```javascript
document.getElementById('f').addEventListener('submit', async (ev) => {
    ev.preventDefault();
    const res = await fetch(`${API}/validate-address`, {
        method: 'POST',
        body: JSON.stringify({
            name: document.getElementById('n').value, 
            email: document.getElementById('e').value, 
            address: document.getElementById('a').value
        })
    });
    
    const r = await res.json();
    
    if (res.status === 200 && r.success && r.data.address) { // ← Validar que address no sea null
        s = r.data;
        document.getElementById('b').disabled = false;
        document.getElementById('o').innerText = 'Data synchronized.';
    } else {
        document.getElementById('o').innerText = 'Address validation failed. Please try again.';
        document.getElementById('b').disabled = true;
    }
});
```

**Recomendación:** Implementar las tres soluciones para una experiencia de usuario robusta y consistente.
