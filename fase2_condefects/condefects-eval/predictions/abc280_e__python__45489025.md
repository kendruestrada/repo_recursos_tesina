# Análisis del Ticket

## Ticket
Se reportan fallos en 10/10 casos de prueba del programa `abc280_e__python__45489025`, a pesar de que el valor numérico calculado coincide exactamente con el esperado en los casos donde se puede verificar el detalle (`example_00`, `hand_00`, `hand_04`).

## Hallazgos en los logs
En los tres casos con detalle mostrado:

- `example_00.txt`: esperado `229596204`, obtenido `229596204` **seguido de** `[0, 1, 698771049, 229596204]`.
- `hand_00.txt`: esperado `1`, obtenido `1` **seguido de** `[0, 1]`.
- `hand_04.txt`: esperado `229895677`, obtenido `229895677` **seguido de** `[0, 1, 928367250, 229895677]`.

En **todos** los casos, el valor numérico correcto se imprime correctamente en la primera línea, pero a continuación aparece una línea adicional con el contenido completo de la lista `dp`. Esto provoca que la salida completa del programa no coincida exactamente con la salida esperada (que solo contiene una línea), generando el fallo en el checker de todos los casos de prueba, incluso cuando el cálculo es matemáticamente correcto.

## Relación con el código fuente
El código implementa correctamente la recurrencia de valor esperado con aritmética modular:

```python
dp=[0,1]
for i in range(N-1):
    dp.append(1+dp[-1]*(100-P)*inv+dp[-2]*P*inv)
    dp[-1]%=mod
print(dp[-1])
print(dp)
```

La lógica de `dp[-1]` y `dp[-2]` es correcta (E[n] = 1 + P(crítico)*E[n-2] + P(normal)*E[n-1]), y `inv` calcula correctamente el inverso modular de 100. El problema **no está en el cálculo**, sino en la última línea:

```python
print(dp)
```

Esta instrucción es un remanente de depuración (debug) que imprime toda la lista `dp`, generando una segunda línea de salida no esperada por el validador del ticket, el cual compara la salida completa contra el resultado esperado (una sola línea con el número).

## Ejemplo de ejecución
Para `N=1, P=0`:

```
dp = [0, 1]
print(dp[-1])  -> "1"
print(dp)      -> "[0, 1]"
```

Salida real del programa:
```
1
[0, 1]
```

Salida esperada:
```
1
```

El checker detecta la discrepancia por la línea extra, marcando el caso como fallido aunque el resultado numérico sea correcto.

## Solución propuesta
Eliminar (o comentar) la línea de depuración final:

```python
print(dp)
```

dejando únicamente:

```python
print(dp[-1])
```

Esto resolverá el fallo en todos los casos de prueba, ya que el cálculo matemático del programa es correcto.
