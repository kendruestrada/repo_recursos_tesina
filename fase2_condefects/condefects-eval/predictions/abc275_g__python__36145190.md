# Análisis del problema

## Ticket
El programa `faultyVersion.py` (solución para ABC275_G) falla en 10/10 casos. Los primeros casos muestran errores mínimos de redondeo (última cifra decimal, atribuibles a la aritmética con `hosei=10**30` y no son el problema central), pero el caso `01_test_05.txt` revela el bug real: se obtiene `635.2762046297652` cuando lo esperado es `9.1438821311792312`, una diferencia de dos órdenes de magnitud que indica un error algorítmico, no de precisión.

## Hallazgos en los logs
- Casos con N pequeño o pocos puntos distintos pasan con error de redondeo insignificante (últimas cifras decimales).
- En casos con N=200000 y muchos puntos cercanos entre sí (test_05), el resultado se desvía drásticamente, indicando que el bucle que recorre las aristas del casco convexo (`Q`) está seleccionando/calculando intersecciones inválidas con la recta `y=x`.

## Relación con el código fuente
El algoritmo construye el casco convexo de los puntos `(a0,b0) = (hosei*a/c, hosei*b/c)` y busca la arista que cruza la diagonal `y=x`, para extraer el valor óptimo.

El test de cruce usado es:
```python
if ((a-c)*(0-b) - (b-d)*(0-a))*((a-c)*(10**100-b) - (b-d)*(10**100-a))<0:
```

Este test comprueba si los puntos **(0,0)** y **(10^100,10^100)** quedan en lados opuestos de la **recta infinita** que contiene al segmento `(c,d)-(a,b)`. Esto **no es equivalente** a comprobar si el segmento real (finito) cruza la línea `y=x`. La condición correcta debería comparar el signo de `(a-b)` y `(c-d)` (es decir, si los extremos del segmento están en lados opuestos de la diagonal), no usar puntos arbitrarios muy alejados como `10**100`.

### Ejemplo de ejecución
Tomando un segmento que NO cruza la diagonal, por ejemplo `(a,b)=(100,90)` y `(c,d)=(80,60)` (ambos puntos están del mismo lado, con `a>b` y `c>d`):

- `outer_product` con `(0,0)`: `20*(0-90) - 30*(0-100) = 1200`
- `outer_product` con `(10**100,10**100)`: `20*(1e100-90) - 30*(1e100-100) ≈ -10e100 + 1200` (negativo, dominado por el término gigante)

Producto: `1200 * (negativo) < 0` → el código concluye **falsamente** que hay cruce, cuando el segmento nunca cruza `y=x`. Esto provoca que `ANS` se actualice con un valor de intersección espurio, generando resultados completamente erróneos como el observado en `01_test_05.txt`.

## Soluciones propuestas
1. Sustituir el test de cruce por la comparación directa de signos en los extremos del segmento respecto a la diagonal:
   ```python
   if (a-b) * (c-d) < 0:
       ANS = min(ANS, (a*(b-d)/(a-c)-b)/((b-d)/(a-c)-1))
   ```
2. Revisar también las ramas degeneradas (`a==c`, `b==d`) para verificar que el punto de intersección esté realmente dentro del rango `[min(b,d), max(b,d)]` o `[min(a,c), max(a,c)]` antes de actualizar `ANS`.
3. Eliminar o ajustar el umbral arbitrario `if (a-c)**2+(b-d)**2<1000: continue`, ya que con `hosei=10**30` este filtro puede descartar aristas legítimas que sí deberían evaluarse.
