# Análisis del Ticket

## Ticket
El programa `abc269_b__python__45961458.py` debe encontrar el rectángulo delimitador (bounding box) de las celdas marcadas con `#` en una grilla de 10x10, imprimiendo la fila mínima/máxima y columna mínima/máxima. Sin embargo, el programa falla en 7 de 10 casos de prueba, siempre fallando en el valor de la fila máxima (`b`).

## Hallazgos en los logs

Observando los casos fallidos:
- **sample_01.txt**: esperado `5 8`, obtenido `5 1` → el primer número (fila mínima) es correcto, pero la fila máxima es incorrecta.
- **sample_03.txt**: esperado `1 10`, obtenido `1 1` → mismo patrón.
- **test_03.txt**: esperado `5 6`, obtenido `5 1` → mismo patrón.

En todos los casos, el valor de `b` (fila máxima) permanece en su valor inicial (0), sumando 1 al imprimir da como resultado "1". Esto indica que la variable `b` nunca se actualiza correctamente durante el recorrido de la grilla, a pesar de que sí se actualizan correctamente `a`, `c` y `d`.

En cambio, en el caso exitoso `test_17.txt`, solo hay un `#` en la posición (0,0), por lo que `a=0, b=0, c=0, d=0` son válidos sin necesitar actualización de `b`, lo cual explica por qué ese caso pasa sin detectar el bug.

## Relación con el código fuente

```python
a,b,c,d = 100, 0, 100, 0
for i in range(n):
    for j in range(n):
      if s[i][j]=='#':
        if a>i : a=i
        if b<i : B=i      # <--- BUG: variable incorrecta
        if c>j : c=j
        if d<j : d=j
print(a+1,b+1)
print(c+1,d+1)
```

El bug está en la línea:
```python
if b<i : B=i
```

Aquí se compara `b` con `i`, pero en caso de cumplirse la condición, se asigna el valor a **`B`** (mayúscula) en lugar de **`b`** (minúscula). Esto crea una nueva variable global `B` que nunca se usa, mientras que `b` permanece con su valor inicial de `0` durante toda la ejecución. Como Python es sensible a mayúsculas/minúsculas, `B` y `b` son variables completamente distintas.

## Ejemplo de ejecución

**Entrada (sample_01.txt):**
```
..........
..........
..........
..........
...######.
...######.
...######.
...######.
..........
..........
```

**Simulación paso a paso:**
- Se recorre la grilla y se detectan `#` en las filas 4,5,6,7 (índices 0-based) y columnas 3-8.
- `a` correctamente llega a `4` (fila mínima, índice 0-based).
- `c` correctamente llega a `3` (columna mínima).
- `d` correctamente llega a `8` (columna máxima).
- **`b` nunca se actualiza** porque cada vez que `b < i` es verdadero, se asigna a `B`, no a `b`. Por lo tanto `b` permanece en `0`.

**Salida obtenida:**
```
5 1    # a+1=5, b+1=1 (incorrecto, debería ser b+1=8)
4 9    # c+1=4, d+1=9 (correcto)
```

**Salida esperada:**
```
5 8
4 9
```

Esto confirma que el bug es la asignación a la variable incorrecta `B` en lugar de `b`.

## Solución propuesta

Corregir el nombre de la variable en la línea afectada:

```python
if b<i : b=i
```

Con este cambio, el código quedaría:

```python
n = 10
s = [input()for i in range(n)]

a,b,c,d = 100, 0, 100, 0
for i in range(n):
    for j in range(n):
      if s[i][j]=='#':
        if a>i : a=i
        if b<i : b=i
        if c>j : c=j
        if d<j : d=j
print(a+1,b+1)
print(c+1,d+1)
```

Esto garantiza que `b` se actualice correctamente con el índice de fila máximo donde aparece un `#`, corrigiendo el bounding box calculado.
