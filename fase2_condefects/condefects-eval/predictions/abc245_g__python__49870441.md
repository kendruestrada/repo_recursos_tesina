## Análisis del problema

**Ticket:** El programa implementa una variante de Dijkstra multi‑fuente con dos "colores" (etiquetas de origen) por nodo, usada para resolver ABC245G. En el caso `hand_03.txt` el resultado obtenido difiere del esperado únicamente en el primer valor de la salida: se obtiene `3000000000` en lugar de `2000000000` (una diferencia de exactamente `1e9`, valor típico de un peso de arista). El resto de los valores coincide, lo que indica que el error no es estructural (no hay excepción ni crash) sino un fallo lógico puntual en la actualización de la "segunda mejor distancia" (`dist2`) para algunos nodos.

## Hallazgos en los logs

- El log muestra `[FAIL] hand_03.txt` con una diferencia acotada: solo el primer número del vector de salida es incorrecto (excede en `1,000,000,000` al valor esperado), mientras el resto de la secuencia es idéntica.
- No hay excepciones ni errores de ejecución: el programa termina correctamente pero produce un valor numérico erróneo, lo cual apunta a un bug de lógica (comparación) y no a un error de tipo/índice.

## Relación con el código fuente

El algoritmo mantiene, para cada nodo, la mejor distancia (`dist1`/`fromColor1`) y la segunda mejor distancia proveniente de un color distinto (`dist2`/`fromColor2`). La respuesta final usa `dist2` cuando el color de origen de `dist1` coincide con el color propio del nodo.

La actualización de `dist2` se realiza en:

```python
elif dist1[next] < nextDist < dist2[next] and fromColor1[next] != curColor:
    dist2[next] = nextDist
    fromColor2[next] = curColor
    heappush(pq, (dist2[next], next, curColor))
```

Aquí se exige que `nextDist` sea **estrictamente mayor** que `dist1[next]`. Sin embargo, si llega un camino con distancia **igual** a `dist1[next]` pero de un color distinto (`fromColor1[next] != curColor`), ese valor también es un candidato válido y potencialmente óptimo para `dist2[next]` (un "empate" con distinto color). Al excluir el caso de igualdad (`<` en vez de `<=`), el algoritmo puede dejar `dist2[next]` con un valor mayor al real, generando una distancia final inflada para los nodos cuyo color coincide con `fromColor1`, exactamente el patrón observado (`3000000000` en vez de `2000000000`, difiriendo por el peso de una arista no considerada correctamente).

## Ejemplo de ejecución (hipotético)

Supongamos 3 nodos, colores `[A, B, ...]`, dos críticos: nodo `X` color `A` a distancia 0, nodo `Y` color `B` a distancia 0. Si ambos caminos llegan a un nodo `Z` con la **misma distancia** `d`, pero colores distintos (`A` y `B`), el código:
- Fija `dist1[Z] = d`, `fromColor1[Z] = A` (el primero en llegar).
- Al llegar el segundo camino (color `B`, misma distancia `d`), la condición `dist1[Z] < nextDist` es `False` (son iguales), por lo que el `elif` tampoco se cumple (`d < nextDist` es falso). 
- `dist2[Z]` permanece en `INF` (o en un valor mayor obtenido por otra ruta más larga), en vez de fijarse en `d`.
- Si el color propio de `Z` es `A`, la respuesta usará `dist2[Z]` (mayor que el real `d`), produciendo un resultado inflado — tal como el `+1e9` observado.

## Solución propuesta

Cambiar la comparación estricta por una que permita la igualdad, para capturar el caso de "empate con color distinto":

```python
elif dist1[next] <= nextDist < dist2[next] and fromColor1[next] != curColor:
    dist2[next] = nextDist
    fromColor2[next] = curColor
    heappush(pq, (dist2[next], next, curColor))
```

Esto garantiza que `dist2` refleje correctamente la menor distancia posible proveniente de un color distinto al de `dist1`, incluso cuando esa distancia coincide exactamente con `dist1`.

Como prueba adicional, se recomienda generar un caso de prueba mínimo donde dos críticos de colores distintos alcancen un mismo nodo con exactamente la misma distancia, y verificar que la respuesta para ese nodo (cuando su color coincide con el color ganador) sea igual a esa distancia y no un valor superior.
