## Análisis del problema

**Ticket:** El programa `faultyVersion.py` falla al procesar la entrada "Friday", devolviendo una salida vacía en lugar de "1".

**Hallazgos en los logs:** El caso `test_04.txt` con entrada `Friday` esperaba la salida `1`, pero el programa no produjo ninguna salida (obtenido: vacío). Esto indica que ninguna de las condiciones `if` del código coincidió con el string de entrada.

**Relación con el código fuente:** El programa compara la variable `s` contra los días de la semana en inglés usando comparaciones exactas de string (`if s=="..."`). Al revisar las condiciones:

```python
if s=="Monday":
    print(5)
if s=="Tuesday":
    print(4)
if s=="Wednesday":
    print(3)
if s=="Thursday":
    print(2)
if s=="Friay":
    print(1)
```

Se detecta que la comparación para el día "Friday" está mal escrita como `"Friay"` (falta la letra **d**). Como Python realiza comparación literal de strings, `"Friday" == "Friay"` es `False`, por lo que ninguna rama se ejecuta y el programa no imprime nada, coincidiendo exactamente con el comportamiento reportado en el log (`obtenido:` vacío).

Adicionalmente, se observa que el programa tampoco maneja los casos `"Saturday"` y `"Sunday"`, lo cual es una falla de cobertura lógica, pero no es la causa del fallo reportado en este log específico.

**Ejemplo de ejecución:**

```python
s = "Friday"
if s == "Friay":   # "Friday" != "Friay" -> False
    print(1)
# No se imprime nada -> salida vacía
```

Esto confirma que el bug reportado corresponde exactamente al typo en la comparación de string.

**Solución propuesta:** Corregir el typo cambiando `"Friay"` por `"Friday"`:

```python
if s=="Friday":
    print(1)
```

Se recomienda además agregar los casos faltantes para `"Saturday"` y `"Sunday"` (imprimiendo por ejemplo `0` o el valor correspondiente según la lógica del ejercicio), para evitar fallos similares en casos no cubiertos por los logs actuales.
