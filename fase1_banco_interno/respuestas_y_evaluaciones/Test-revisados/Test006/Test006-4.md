### Analysis

## Hallazgos en los logs

Al analizar los logs de CloudWatch, se identificaron múltiples errores recurrentes con el mensaje:

```
"Checkout rechazado por inconsistencia de precio"
```

**Ejemplos específicos encontrados:**
- ProductId: PROD-233, Precio mostrado: 154, Precio real en DB: 56.0
- ProductId: PROD-754, Precio mostrado: 125, Precio real en DB: 92.0  
- ProductId: PROD-086, Precio mostrado: 152, Precio real en DB: 62.0
- ProductId: PROD-499, Precio mostrado: 164, Precio real en DB: 77.0

**Patrón identificado:** En todos los casos, el precio mostrado al usuario es significativamente mayor que el precio real almacenado en la base de datos.

## Relación con el código fuente

### 1. **Función de Checkout (inventory_check/app.py)**
```python
if abs(db_price - expected_price) > 0.01:
    logger.error(
        "Inconsistencia de precio detectada",
        productId=product_id,
        precioQueMostroCache=expected_price,
        precioRealEnDB=db_price,
        diferencia=round(expected_price - db_price, 2),
    )
    return {
        "valid": False,
        "error": "Precio manipulado o desactualizado",
        "expectedPrice": expected_price,
        "actualPrice": db_price,
    }
```

### 2. **Función de obtención de precios (product_pricing/app.py)**
```python
cache_key = f"price:{product_id}"
cached_price = redis_client.get(cache_key)

if cached_price:
    price = float(cached_price)
    # Retorna precio desde cache
else:
    # Consulta DB y actualiza cache
    redis_client.setex(cache_key, CACHE_TTL, str(price))
```

### 3. **Función de invalidación de cache (cache_invalidation/app.py)**
```python
cache_key = f"price:{product_id}"
deleted = redis_client.delete(cache_key)
```

## Causa raíz identificada

**PROBLEMA PRINCIPAL: Race Condition en la invalidación del cache**

1. **Flujo problemático:**
   - Admin actualiza precio en DB (update_price/app.py)
   - DynamoDB Stream dispara cache_invalidation function
   - Pero existe un delay entre la actualización de DB y la invalidación del cache
   - Durante este período, los usuarios obtienen precios obsoletos del cache

2. **Ventana de inconsistencia:**
   - El cache tiene TTL de 3600 segundos (1 hora)
   - Si no se invalida correctamente, los precios antiguos persisten
   - Los usuarios ven precios desactualizados hasta que expire el TTL

## Ejemplo de ejecución

**Escenario problemático:**
```
T0: Precio en DB = $50, Cache = $50
T1: Admin actualiza precio DB a $100
T2: Usuario consulta precio → obtiene $50 del cache (aún no invalidado)
T3: Usuario intenta checkout con precio $50
T4: Sistema valida contra DB ($100) → ERROR: "precio manipulado"
```

## Soluciones propuestas

### **Solución 1: Invalidación síncrona del cache**
Modificar `update_price/app.py` para invalidar el cache inmediatamente:

```python
import redis

redis_client = redis.Redis(host=REDIS_ENDPOINT, port=REDIS_PORT, decode_responses=True)

@logger.inject_lambda_context
def lambda_handler(event, context):
    # ... código existente ...
    
    # Después de actualizar DB
    table.update_item(...)
    
    # Invalidar cache inmediatamente
    cache_key = f"price:{product_id}"
    redis_client.delete(cache_key)
    
    logger.info("Cache invalidado sincrónicamente", productId=product_id)
```

### **Solución 2: Implementar cache write-through**
Actualizar el cache con el nuevo precio en lugar de solo eliminarlo:

```python
# En update_price/app.py
redis_client.setex(cache_key, CACHE_TTL, str(new_price))
logger.info("Cache actualizado con nuevo precio", productId=product_id, precio=new_price)
```

### **Solución 3: Validación con tolerancia temporal**
Modificar `inventory_check/app.py` para permitir una pequeña ventana de gracia:

```python
# Verificar timestamp de última actualización
if abs(db_price - expected_price) > 0.01:
    # Verificar si la actualización fue reciente (últimos 30 segundos)
    if product.get('updatedAt', 0) > (int(time.time()) - 30):
        logger.warning("Precio actualizado recientemente, permitiendo transacción")
        return {"valid": True, "productId": product_id, "price": db_price}
```

### **Solución 4: Implementar versionado de precios**
Agregar un campo de versión para detectar cambios:

```python
# Incluir version en cache key
cache_key = f"price:{product_id}:v{version}"
```

**Recomendación:** Implementar la **Solución 1** como fix inmediato y la **Solución 2** como mejora a largo plazo para optimizar el rendimiento del sistema.
