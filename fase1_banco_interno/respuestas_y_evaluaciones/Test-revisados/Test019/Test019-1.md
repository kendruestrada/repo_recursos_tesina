###Analysis

**Ubicacion:** `product_service/app.py`, lineas 51 y 74

**Pasos para reproducir:**
1. Llamar al endpoint con `GET /search?category=electronics&page=1&limit=2`
2. Llamar al endpoint con `GET /search?category=electronics&page=2&limit=2`
3. Ambas respuestas retornan exactamente los mismos items

**Expected vs Actual:**

| Request | Esperado | Actual |
|---|---|---|
| `page=1&limit=2` | items[0:2] | items[0:2] |
| `page=2&limit=2` | items[2:4] | items[0:2] (mismo resultado) |
| `page=3&limit=2` | items[4:6] | items[0:2] (mismo resultado) |

**Analisis del flujo:**

En `app.py:35-39`, el parametro `page` se lee correctamente:
```python
page = int(query_params.get("page", 1))
```

Sin embargo, en `app.py:51`, `fetch_limit` se calcula ignorando `page`:
```python
fetch_limit = limit          # Bug: deberia ser page * limit
```

Y en `app.py:74`, el slice no considera el offset de pagina:
```python
items = all_items[:fetch_limit]   # Bug: deberia ser all_items[(page-1)*limit : page*limit]
```

El resultado es que la funcion siempre consulta y retorna los primeros `limit` items de DynamoDB, sin importar que `page` se solicite. El valor de `page` solo aparece en el log (linea 47) y en el response body (linea 88), pero no influye en los datos devueltos.

### Solution

Para implementar paginacion offset sobre DynamoDB (que usa paginacion por cursor), se debe:

1. Calcular `fetch_limit = page * limit` para obtener suficientes items hasta la pagina solicitada
2. Extraer el slice correcto: `items = all_items[(page - 1) * limit : page * limit]`

```python
# app.py:51 - correccion
fetch_limit = page * limit   # Obtener items suficientes hasta la pagina solicitada

# ...resto del loop sin cambios...

# app.py:74 - correccion
start = (page - 1) * limit
items = all_items[start : start + limit]
```

**Nota adicional:** Este enfoque de paginacion por offset en DynamoDB implica leer y descartar `(page-1)*limit` items en cada request, lo cual se vuelve costoso para paginas altas. Para produccion se recomienda usar paginacion por cursor (`LastEvaluatedKey`) como parametro de entrada en lugar de un numero de pagina.
