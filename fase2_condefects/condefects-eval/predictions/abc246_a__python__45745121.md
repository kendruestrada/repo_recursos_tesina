## Análisis del problema

**Ticket:** El programa recibe tres pares de coordenadas que representan tres vértices de un rectángulo (con lados paralelos a los ejes) y debe calcular las coordenadas del cuarto vértice faltante. La salida esperada es el par de números separados por un espacio (formato típico de competitive programming: `-100 -100`), pero el programa está devolviendo la representación de una lista de Python (`[-100, -100]`).

**Hallazgos en los logs:**
Todos los casos fallan de la misma manera: el valor numérico calculado es **correcto** (`-100 -100`, `-100 100`, `100 100`), pero el formato de salida no coincide con el esperado. En cada caso el resultado obtenido aparece entre corchetes y con coma, típico de imprimir una lista de Python directamente con `print()`.

**Relación con el código fuente:**
La lógica de cálculo (los bloques `if/elif/else` que comparan coordenadas de `xy1`, `xy2` y `xy3` para deducir el vértice faltante) es correcta, como se verifica al simular manualmente el caso `000.txt`:

- Para la coordenada X: ninguna coincide → se toma `xy1[0] = -100` ✅
- Para la coordenada Y: `xy1[1] == xy2[1]` → se toma `xy3[1] = -100` ✅

El resultado interno `x = [-100, -100]` es matemáticamente correcto. El problema está en la línea final:

```python
print(x)
```

Esta instrucción imprime la lista de Python tal cual (`[-100, -100]`), en lugar de imprimir los dos valores separados por un espacio como exige el formato de salida del juez (`-100 -100`).

**Ejemplo de ejecución:**
Entrada:
```
-100 100
100 100
100 -100
```
- `x` calculado internamente: `[-100, -100]`
- Salida obtenida: `[-100, -100]`
- Salida esperada: `-100 -100`

**Solución propuesta:**
Cambiar la línea `print(x)` por una que imprima los elementos separados por espacio, por ejemplo:
```python
print(*x)
```
o bien:
```python
print(x[0], x[1])
```
